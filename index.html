Core Mental Model

Data becomes useful through a process

The course separates raw data from useful insight. Data must be asked about, prepared, processed, analyzed, shared, and acted on before it can improve a decision.

Module 1: Introducing Data Analytics And Analytical Thinking

Goal: understand what data analytics is, how analysts think, and how data turns into decisions.

1. What Data Analytics Means

Data analytics is the discipline of using data, tools, methods, and reasoning to understand a situation and support better decisions. A data analyst does not simply collect numbers. The analyst clarifies the question, finds relevant data, prepares it, studies patterns, checks whether conclusions are fair, and communicates what should happen next.

  • Data is a collection of facts. It can be numbers, text, dates, images, survey responses, logs, transactions, or observations.
  • Data analysis is the work of collecting, transforming, and organizing data to draw conclusions.
  • Data analytics is the broader science and practice around data work, including tools, workflows, systems, and decision-making.

2. Data In Everyday Life

The course starts with ordinary examples because analytics is not limited to big companies. You use data whenever you compare prices, track exercise, check exam performance, plan travel, or decide what content performs better. The professional difference is that analysts make the process deliberate, documented, repeatable, and useful for others.

  • A shop can use sales data to decide inventory.
  • A school can use attendance and scores to identify support needs.
  • A product team can use usage data to understand where users struggle.
  • A public organization can use data to allocate services more fairly.

3. Data Types And Spreadsheet Thinking

Early spreadsheet work trains you to notice how data is structured. Every column should represent a field, every row should represent an observation, and every value should match the expected type. Before analysis, check whether data is numeric, text, date/time, categorical, Boolean, or mixed. Wrong data types lead to wrong sorting, broken formulas, misleading charts, and bad conclusions.

4. The Data Ecosystem

A data ecosystem is the connected environment where data is produced, stored, managed, analyzed, and shared. It includes people, tools, data sources, databases, cloud storage, business processes, policies, and the decisions that come from analysis. The course emphasizes that analysts work inside this ecosystem rather than in isolation.

  • Sources: transactions, websites, sensors, surveys, social platforms, HR systems, finance systems, and operational tools.
  • Storage: spreadsheets, databases, warehouses, and cloud systems.
  • Tools: spreadsheets, SQL, dashboards, visualization tools, notebooks, and reporting systems.
  • People: analysts, stakeholders, managers, customers, engineers, and decision-makers.

5. Analysts, Scientists, And The Analytics Umbrella

The course separates common terms. Data analysts often answer existing business questions by creating insights from available data. Data scientists often create new models, experiments, and ways to understand unknown patterns from raw data. In practice, roles overlap, but the foundation is the same: ask clear questions, respect data quality, and communicate honestly.

6. Core Skills Of A Data Analyst

A strong analyst combines technical skill with business judgment. Technical skill helps you clean, query, calculate, and visualize. Analytical skill helps you understand what matters. Communication skill helps others trust and use the result.

CuriosityKeep asking why the pattern exists, what is missing, and what else could explain the result.
ContextUnderstand the business situation, audience, constraints, and decision being made.
Technical mindsetBreak problems into steps and use tools carefully.
Data designOrganize data so it can be used correctly and efficiently.
Data strategyThink about how people, processes, and tools support long-term data use.
CommunicationExplain findings in plain language and connect them to action.

7. Analytical Thinking And The Five Whys

Analytical thinking means approaching problems with structure. Instead of accepting the first explanation, analysts ask follow-up questions, test assumptions, and look for evidence. The five whys method is a simple root-cause tool: ask why a problem happened, then ask why again for each answer until you reach a cause that can be acted on.

  • Separate analyst and scientist responsibilities.

  • Use the five whys on a real problem.

Memory Hooks

  • Data is raw material; insight is usable meaning.
  • Analysis answers a question; analytics is the wider discipline.
  • Good analysts combine tools, context, and communication.

Module 2: The Wonderful World Of Data

Goal: distinguish the data life cycle from the data analysis process and understand how analysts choose tools.

1. Data Life Cycle

The data life cycle describes what happens to data over time. It is about the data itself, not just the analyst's work. Different organizations may use slightly different names, but the idea is stable: data is planned, captured, managed, analyzed, archived, and eventually destroyed or retired.

PlanDecide what data is needed, why it is needed, who owns it, and how it should be collected.
CaptureCollect or generate the data through forms, systems, sensors, transactions, or imports.
ManageStore, secure, organize, document, and maintain the data.
AnalyzeUse the data to identify patterns, answer questions, and create insight.
ArchiveMove data out of active use while keeping it available if needed.
DestroyDelete data safely when it is no longer needed or legally allowed to be kept.

2. Data Analysis Process

The data analysis process describes the analyst's workflow. It is the most important operating model in the certificate because later courses map to these phases. A good analyst moves through the phases intentionally, but may loop backward when a problem appears.

AskDefine the business problem, stakeholders, scope, success measure, and decision.
PrepareIdentify, collect, inspect, and understand the relevant data sources.
ProcessClean, transform, validate, and organize data for analysis.
AnalyzeExplore patterns, calculate metrics, compare groups, and test ideas.
ShareCommunicate findings with visuals, reports, dashboards, and recommendations.
ActHelp stakeholders use the insight to make or improve a decision.

3. Life Cycle vs Analysis Process

Do not mix these two models. The life cycle is about the life of data in an organization. The analysis process is about how an analyst solves a question. For example, archiving old customer records belongs to the data life cycle. Asking why customer retention dropped belongs to the data analysis process.

4. Analyst Tools

The course introduces tools as choices, not as trophies. A tool is good only when it fits the task. Analysts often move from spreadsheets to SQL to visualization as the work grows in scale and communication needs.

SpreadsheetsBest for smaller tables, quick calculations, sorting, filtering, formulas, pivot-style summaries, and simple charts.
SQLBest for querying databases, filtering large tables, joining related tables, and creating repeatable data pulls.
Visualization toolsBest for dashboards, charts, stakeholder communication, trend monitoring, and interactive exploration.
DocumentationBest for making assumptions, definitions, and decisions understandable to future users.

5. Choosing The Right Tool

Ask these questions before choosing a tool: How large is the data? Where does it live? Does the work need to be repeated? Who will use the output? Does the audience need details, a chart, or a decision-ready summary? A spreadsheet may be enough for a quick class exercise, but SQL is better when data is stored in a database and must be joined or filtered reliably.

Module 2 Revision Checklist

  • Recite the six data life cycle stages.
  • Recite ask, prepare, process, analyze, share, act.
  • Classify examples as life cycle or analysis process.
  • Choose spreadsheet, SQL, or visualization for a scenario.

Memory Hooks

  • Life cycle: what happens to data.
  • Analysis process: what analysts do with data.
  • Tool choice depends on task, scale, source, and audience.

Module 3: Set Up Your Data Analytics Toolbox

Goal: understand the basic role of spreadsheets, SQL, and data visualization in analysis work.

1. Spreadsheet Basics

Spreadsheets are often the first analysis tool because they are visual, flexible, and easy to start with. They help you enter data, format tables, calculate values, sort rows, filter records, build quick summaries, and create simple charts. A good spreadsheet has clean headers, consistent data types, one observation per row, and one field per column.

  • Use formulas to calculate values from existing fields.
  • Use sorting to reorder data by a meaningful field.
  • Use filtering to focus on a subset of rows.
  • Use charts to inspect relationships, trends, or comparisons.
  • Keep raw data separate from calculations or presentation views when possible.

2. Common Spreadsheet Risks

Spreadsheets become risky when data grows large, multiple people edit without rules, formulas are copied incorrectly, or there is no documentation. Always check field names, date formats, blank values, duplicates, outliers, and formula ranges. If the analysis must run repeatedly or across large tables, move toward databases and SQL.

3. SQL Basics

SQL is a language for working with databases. Instead of manually scrolling through rows, you write instructions to select, filter, sort, aggregate, and combine data. The course introduces SQL as a core analyst tool because real organizations often store data in structured databases.

SELECTChoose the columns you want to return.
FROMChoose the table where the data lives.
WHEREFilter rows by a condition.
ORDER BYSort the result.
GROUP BYSummarize rows by category.
JOINCombine related tables using a shared key.

4. Why SQL Matters

SQL makes analysis more reliable because the query can be saved, reviewed, rerun, and adjusted. It reduces manual copying and helps analysts work with much larger datasets than spreadsheets can comfortably handle. Even when the final output is a spreadsheet or dashboard, SQL often does the heavy lifting behind it.

5. Data Visualization

Visualization is the practice of representing data visually so people can understand patterns quickly. A chart should serve a question. Before creating a visualization, decide the audience, message, data fields, comparison type, and action needed. The wrong chart can hide the truth or suggest the wrong conclusion.

  • Use a line chart for trends over time.
  • Use a bar chart for comparing categories.
  • Use a scatter plot for relationships between two numeric variables.
  • Use tables when exact values matter more than visual pattern recognition.
  • Use clear labels, units, scales, and titles.

6. Planning A Visualization

A strong visualization plan starts with the stakeholder question. Ask: What decision will this support? What should the viewer notice first? What context is required? What could be misunderstood? What data is missing? Good visuals simplify without hiding uncertainty.

Module 3 Revision Checklist

  • Describe when spreadsheets are useful.
  • Name spreadsheet quality checks.
  • Explain SQL's role in database work.
  • Write the purpose of SELECT, FROM, WHERE, GROUP BY, and ORDER BY.
  • Choose a chart type for a business question.

Memory Hooks

  • Spreadsheets are flexible; SQL is scalable; visualization is communicative.
  • Charts must answer questions, not decorate reports.
  • Tool fluency grows through repeated practice.

Module 4: Become A Fair And Impactful Data Professional

Goal: connect data analysis to business roles, fairness, ethical decisions, and career readiness.

1. What Data Analysts Do In Business

Data analysts help organizations understand what happened, why it happened, what could happen next, and what action might improve the situation. They work with stakeholders in marketing, finance, operations, HR, product, healthcare, education, government, and many other areas. Their value comes from connecting evidence to decisions.

  • Clarify business problems and define useful questions.
  • Collect and inspect relevant data.
  • Clean and transform data for reliable analysis.
  • Find patterns, trends, relationships, and anomalies.
  • Share insights through reports, dashboards, presentations, and conversations.

2. Analyst Roles And Job Descriptions

Job titles vary, but the foundation is similar. A junior analyst may focus on reports, spreadsheets, dashboards, and SQL queries. A business analyst may focus more on stakeholder needs and process improvement. A data analyst may work deeply with data cleaning, metrics, and visualization. Read job descriptions by looking for required tools, domain knowledge, communication expectations, and examples of business problems.

3. Data In Different Industries

The same analytical thinking appears in different forms. Retail analysts study customers, sales, inventory, and promotions. HR analysts study hiring, retention, and employee experience. Agriculture can use weather, soil, sensor, and yield data. Healthcare can use appointment, patient, operations, and outcome data. The industry changes the context, but the analyst still asks, prepares, processes, analyzes, shares, and acts.

4. Fairness And Ethics

Fairness means the data work should not unfairly exclude, misrepresent, or harm people. A technically correct calculation can still support an unfair decision if the data is biased, incomplete, or used without context. Ethical analysts question the data source, collection method, representation, privacy, and consequences of recommendations.

RepresentationWho is included in the data, and who is missing?
BiasCould collection, labels, history, or assumptions tilt the result?
PrivacyDoes the work protect sensitive or personal information?
TransparencyCan stakeholders understand how the conclusion was reached?
ContextDoes the recommendation respect the real-world situation?
ImpactWho benefits, who carries risk, and what could go wrong?

5. Making Fair Business Decisions

Before acting on data, ask whether the question is fair, the data is appropriate, the analysis is valid, and the recommendation is proportional. Do not use data just because it is available. Use data because it is relevant, reliable, and appropriate for the decision.

  • Check whether the metric truly measures the business goal.
  • Look for missing groups or distorted samples.
  • Avoid confusing correlation with causation.
  • Explain assumptions and uncertainty.
  • Give stakeholders enough context to act responsibly.

6. Career Readiness

The course closes by positioning data analytics as a career path. To prepare for roles, build evidence of your skills: projects, dashboards, SQL examples, spreadsheet work, written explanations, and business recommendations. In interviews, explain your process clearly: the problem, data, method, finding, recommendation, and impact.

Module 4 Revision Checklist

  • Explain what analysts do for businesses.
  • Read a job description and identify tool, domain, and communication requirements.
  • Give one analytics example from three industries.
  • Run a fairness check on a business decision.
  • Prepare a short project story using problem, method, result, and action.

Memory Hooks

  • Impact = evidence plus action.
  • Fairness is part of data quality.
  • A good analyst protects trust, not just accuracy.

Ask Questions to Make Data-Driven Decisions. This reader is designed so you can revise the second course directly from this page.

Module 1: Ask Effective Questions

Goal: turn vague business issues into clear, answerable, decision-ready questions.

1. Why Questions Matter

Data analysis begins before data is opened. The first job is to understand the problem well enough to ask useful questions. A vague request such as "sales are bad" is not analysis-ready. An analyst turns it into questions about time period, customer segment, product category, region, comparison baseline, business impact, and possible action.

2. From Issue To Action

The course repeats the six analysis phases from Course 1, but Course 2 uses them more practically. The analyst starts with an issue, asks the right questions, prepares and processes the right data, analyzes evidence, shares findings, and helps stakeholders act.

Diagram: Issue To Action Flow

IssueA business situation feels unclear, risky, expensive, or promising.
QuestionThe analyst defines what must be answered and for whom.
EvidenceRelevant data is prepared, checked, and analyzed.
DecisionFindings are shared so stakeholders can act.

3. Common Problem Types

Many business questions fall into repeatable problem types. Naming the type helps you choose the right data, comparison, and analysis method.

Making predictionsEstimate what is likely to happen next, such as future demand or churn risk.
Categorizing thingsGroup items, users, transactions, or cases into meaningful categories.
Spotting something unusualFind anomalies, outliers, errors, fraud signals, or unexpected changes.
Identifying themesFind repeated patterns in qualitative or open-ended information.
Discovering connectionsExplore relationships between variables, events, or behaviors.
Finding patternsLook for trends, seasonality, recurring behavior, or repeated outcomes.

4. SMART Questions

SMART questions are specific, measurable, action-oriented, relevant, and time-bound. They prevent wasted work because they clarify what decision the data should support. A SMART question does not ask "Are customers unhappy?" It asks something like, "Which customer segment had the largest increase in support complaints in the last quarter, and what action can reduce repeat complaints?"

Diagram: SMART Question Builder

SSpecific: name the group, metric, event, or decision.
MMeasurable: define what can be counted or compared.
AAction-oriented: connect the answer to a possible action.
RRelevant: tie the question to the business goal.
TTime-bound: set the period or deadline.

5. Strong vs Weak Questions

Weak questions are leading, vague, closed too early, or disconnected from action. Strong questions are open enough to explore, focused enough to answer, and neutral enough to avoid pushing the analyst toward a preferred conclusion.

  • Weak: "Did the new policy ruin sales?"
  • Better: "How did sales change after the new policy, compared with the previous period and similar unaffected regions?"
  • Weak: "Which employee caused the issue?"
  • Better: "Which process step is most associated with the issue, and what evidence supports that?"

Module 1 Checklist

  • Convert vague issues into SMART questions.
  • Name the six common problem types.
  • Separate neutral questions from leading questions.
  • Connect every question to a decision.

Memory Hook

  • Question quality controls analysis quality.
  • Problem type tells you what pattern to look for.

Module 2: Make Data-Driven Decisions

Goal: use evidence, metrics, dashboards, and mathematical thinking to support decisions.

1. Data And Decisions

Data-driven decision-making means using evidence to guide action. It does not mean ignoring experience or context. It means decisions should be tested against facts instead of relying only on instinct, hierarchy, or habit. A good decision combines data, business understanding, ethical judgment, and stakeholder needs.

2. Qualitative And Quantitative Data

Quantitative data is numerical and can be counted or measured. Qualitative data is descriptive and captures qualities, opinions, categories, stories, or observations. Both are valuable. Quantitative data can show how much or how often. Qualitative data can explain why people feel or behave a certain way.

QuantitativeRevenue, clicks, time, ratings, age, counts, percentages, and measurements.
QualitativeInterview notes, survey comments, complaint themes, categories, descriptions, and observations.

3. Data Versus Metrics

Data is raw information. A metric is a selected measurement used to track something important. For example, individual order records are data. Average order value is a metric. Good metrics are clearly defined, consistently calculated, tied to goals, and useful for decisions.

4. Sharing Findings

Analysis has value only when people understand and use it. Reports and dashboards help share findings, but they must be designed around the audience. A stakeholder dashboard should highlight the few measures that matter, show trends or comparisons clearly, and make the next action easier.

Diagram: Dashboard Design Path

AudienceWho will use it, and what do they already know?
DecisionWhat choice or monitoring need should it support?
MetricsWhich measures best represent progress or risk?
LayoutWhat should be seen first, compared, filtered, or investigated?

5. Mathematical Thinking

Mathematical thinking is not only formulas. It is the habit of defining quantities, comparing values fairly, checking scale, looking for relationships, and interpreting change carefully. It helps analysts avoid false conclusions from incomplete comparisons.

  • Compare like with like: same time period, same definition, same population.
  • Use percentages carefully; a small base can create dramatic-looking changes.
  • Look at both big-picture totals and smaller segments.
  • Ask whether a difference is meaningful enough to act on.

6. Big And Small Data

Small data can be inspected directly and may fit in spreadsheets. Big data is too large, fast, or complex for simple manual handling and often needs databases, cloud tools, or specialized systems. Size alone does not determine value. The right data is the data that answers the decision question reliably.

Module 2 Checklist

  • Explain data-driven decision-making.
  • Separate data from metrics.
  • Use qualitative and quantitative evidence together.
  • Design a dashboard around audience and decision.
  • Apply mathematical thinking to comparisons.

Module 3: Spreadsheet Magic

Goal: use spreadsheets, formulas, functions, and structured thinking to solve analysis problems.

1. Spreadsheets Across The Data Life Cycle

Spreadsheets can support many stages of the data life cycle: planning fields, capturing small datasets, managing tables, analyzing values, sharing simple charts, and documenting work. They are popular because they are accessible, visual, and flexible.

2. Basic Spreadsheet Tasks

Core tasks include entering data, freezing headers, formatting values, sorting, filtering, creating formulas, using functions, checking data quality, and generating charts. Good spreadsheet habits matter: clear headers, consistent types, no merged data tables, and formulas that can be audited.

3. Formulas And Functions

A formula is an expression you write to calculate a result. A function is a predefined formula built into the spreadsheet tool. Formulas and functions save time, reduce manual work, and make repeated analysis possible.

Diagram: Formula And Function Examples

=B2*C2
row-level calculation
=SUM(D2:D50)

=AVERAGE(E2:E50)

=COUNTIF(A:A,"West")

4. Spreadsheet Errors

Errors are signals that something needs checking. Common spreadsheet issues include wrong ranges, missing values, inconsistent formats, divided-by-zero calculations, typoed references, and formulas copied into the wrong rows. Fix errors by inspecting the formula, source cells, data type, range, and assumptions.

#DIV/0!A formula tries to divide by zero or an empty cell.
#REF!A formula points to a cell or range that no longer exists.
#VALUE!A formula receives the wrong kind of value, such as text where a number is expected.
#NAME?The spreadsheet does not recognize a function name or named range.

5. Structured Thinking

Structured thinking means organizing a problem before trying to solve it. Analysts define the problem, identify inputs, clarify outputs, set boundaries, list assumptions, and choose a method. It reduces confusion and prevents analysis from drifting away from the real business need.

Diagram: Structured Thinking Loop

ProblemWhat exactly needs to be solved?
InputsWhat data, people, and context are needed?
MethodWhat steps, tools, and checks will be used?
OutputWhat decision-ready deliverable is expected?

6. Scope Of Work

A scope of work defines what the project will and will not include. It should identify the problem, stakeholders, deliverables, timeline, data sources, constraints, assumptions, and success criteria. It protects both the analyst and stakeholder because expectations become explicit.

7. Staying Objective

Objectivity means letting evidence guide the conclusion. Analysts should avoid cherry-picking, confirmation bias, personal preference, and pressure to deliver a convenient answer. Context matters because numbers can mislead when the situation behind them is ignored.

Module 3 Checklist

  • Explain formulas versus functions.
  • Recognize common spreadsheet errors.
  • Create a scope of work outline.
  • Use structured thinking before analysis.
  • Explain how context supports objectivity.

Module 4: Always Remember The Stakeholder

Goal: manage stakeholder expectations, communicate clearly, and work well with teams.

1. Stakeholders And Teams

Stakeholders are people who care about the project outcome, influence it, or use its results. A data analyst must balance stakeholder needs with team capacity, data limitations, timeline, and realistic project goals. Clear communication prevents surprises.

Diagram: Stakeholder Alignment Map

Decision-makerNeeds a clear recommendation and confidence level.
Subject expertProvides business context and validates assumptions.
Data ownerKnows source definitions, quality issues, and access rules.
Analyst teamPlans the work, checks quality, and produces the deliverable.

2. Focus On What Matters

Stakeholders may ask for many things. The analyst's job is to keep the work tied to the original business question and decision. If a request expands the project, clarify priority, timeline, and tradeoffs before continuing.

3. Clear Communication

Clear communication is regular, audience-aware, honest, and specific. Use simple language, define metrics, explain assumptions, and separate facts from recommendations. If a project changes, communicate early.

  • Use summaries for executives and detail for technical collaborators.
  • Confirm definitions before analysis begins.
  • Share progress, blockers, and risks before they become surprises.
  • Use visuals when patterns matter and written notes when decisions need context.

4. Speed Versus Accuracy

Data work often involves tradeoffs. A fast answer may be useful for directional decisions, but a high-risk decision may require more validation. Communicate the confidence level and limitations. Never let urgency hide uncertainty.

5. Limitations Of Data

Data can be incomplete, outdated, biased, incorrectly collected, poorly defined, or irrelevant to the question. A professional analyst explains limitations instead of pretending the data is perfect. This protects trust.

6. Meeting And Teamwork Practices

Good meetings have a purpose, agenda, right participants, clear decisions, and next steps. Good teamwork turns conflict into collaboration by clarifying goals, listening carefully, documenting agreements, and returning to evidence when opinions differ.

Module 4 Checklist

  • Identify stakeholder roles in a project.
  • Explain speed versus accuracy tradeoffs.
  • Communicate limitations clearly.
  • Write a meeting agenda for a data project.
  • Turn a stakeholder request into a scoped deliverable.

Memory Hook

  • Stakeholder trust is built through clarity, expectations, and honest limits.
  • Communication is part of analysis, not an afterthought.

Prepare Data for Exploration. This course is about choosing the right data, checking responsibility and credibility, working with databases, and organizing data securely.

Module 1: Data Types And Structures

Goal: decide what data to collect and understand structure, format, fields, values, and transformations.

1. Data Exploration

Data exploration is the early process of understanding what data exists, where it came from, what it contains, and whether it is useful for the question. Before analysis, an analyst checks whether the data fits the business objective, whether important fields are present, and whether the data can be trusted enough to use.

2. Selecting The Right Data

The right data is relevant, reliable, timely, complete enough, and appropriate for the question. More data is not automatically better. Analysts decide what to collect by starting from the decision, then listing the information needed to answer it.

Diagram: Data Selection Filter

QuestionWhat decision or problem is being addressed?
RelevanceDoes the data directly connect to that question?
QualityIs it complete, credible, and usable?
EthicsIs it appropriate and responsible to use?

3. Structured And Unstructured Data

Structured data is organized in a clear table-like format with rows and columns. Unstructured data is not organized in a fixed table, such as text comments, images, videos, audio, or open-ended notes. Semi-structured data has some organization but does not fit a simple table perfectly, such as JSON, XML, or tagged logs.

StructuredSales table, customer database, spreadsheet, transaction records.
UnstructuredReviews, emails, images, call recordings, social posts.
Semi-structuredJSON files, XML, event logs, tagged data.
FormatThe storage or representation type, such as CSV, XLSX, SQL table, JSON, or PDF.

4. Data Types, Fields, And Values

A field is a column or attribute. A value is one entry in a field. A table is useful when each field has a consistent type and each row represents one observation. Common data types include number, text/string, date/time, Boolean, category, and currency.

5. Boolean Logic

Boolean logic uses TRUE/FALSE conditions to filter data. Analysts use AND, OR, and NOT to include or exclude records. Example: region = "North" AND revenue > 10000 returns records that satisfy both conditions.

6. Wide And Long Data

Wide data stores repeated measurements across multiple columns. Long data stores repeated measurements down rows, often with a variable column and a value column. Long data is often easier for analysis, visualization, and grouping.

Diagram: Wide vs Long Data

WideRegion | Jan Sales | Feb Sales | Mar Sales
LongRegion | Month | Sales

Module 1 Checklist

  • Explain structured, semi-structured, and unstructured data.
  • Identify fields, values, and data types.
  • Use AND, OR, and NOT for filtering logic.
  • Recognize wide and long data formats.

Module 2: Data Responsibility

Goal: check bias, credibility, ethics, privacy, anonymization, and open-data responsibility before using data.

1. Bias From Questions To Conclusions

Bias can enter at every stage: the question asked, the sample collected, the data source chosen, the processing decisions, the interpretation, or the final recommendation. Responsible analysts actively look for bias instead of assuming data is neutral.

2. Credible Data

Credible data is accurate, complete enough, unbiased as far as possible, current for the question, and from a trustworthy source. Bad data can be incorrect, duplicated, missing, outdated, biased, inconsistent, or collected for a purpose that does not match the current analysis.

Diagram: Credibility Checklist

AAccurate
CComplete
CCurrent
SSource-trusted
FFit for purpose

3. Data Ethics And Privacy

Data ethics means using data in ways that are fair, transparent, accountable, and respectful. Privacy means protecting personal or sensitive information. Analysts should only use data that is necessary, authorized, and appropriate.

  • Collect only what is needed.
  • Protect sensitive fields.
  • Explain intended data use clearly.
  • Avoid exposing personal information.
  • Document assumptions and limitations.

4. Data Anonymization

Anonymization removes or transforms identifying information so individuals cannot reasonably be recognized. Examples include removing names, masking email addresses, aggregating small groups, and replacing exact dates with broader periods.

5. Open Data

Open data is data made available for public use. It can support transparency and innovation, but it still requires ethical handling. Analysts must check licensing, source credibility, privacy risk, and whether the data is appropriate for the question.

Module 2 Checklist

  • Find possible bias in a question or dataset.
  • Judge whether a source is credible.
  • Explain data ethics and privacy.
